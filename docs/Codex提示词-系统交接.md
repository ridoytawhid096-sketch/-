## 提示词正文

你要为锐兴管理系统写一份**完整的系统交接文档**，读者是一位看不到源码的架构师（Claude）。他要靠这份文档重新简化设计整个系统，所以要写得**详细、准确、有出处**。每一条结论都要标注来源：`文件路径:行号`，或者 SQL 查询。

源码位置：`/Users/moumou/ruixing`

### 一、铁律（必须遵守，违反任何一条就停下来问我）

1. **全程只读。** 不修改、不新建、不删除源码目录里的任何文件。不执行 git commit / checkout / reset / stash / pull / push，只允许 `git log`、`git status`、`git diff`、`git branch`、`git show` 这类查看命令。
2. **不碰正式数据库。** 先找到最近的数据库备份，复制一份到 `/tmp/ruixing-handoff/`，只对这份副本做查询，并用只读方式打开（`sqlite3 -readonly`，或 `file:...?mode=ro`）。找不到备份，或者分不清哪个是正式库、哪个是备份，就停下来问我。
3. **不启动、不重启正式服务**，不调用任何外部接口（地图、短信、企微等）。
4. **不输出任何个人信息。** 文档里不能出现客户、家长、老师、员工的真实姓名、电话、微信号、详细地址。需要举例时用 ID（例如"客户 #1234"）或"员工A"。统计只给数量和金额汇总。
5. **不输出任何密钥。** `.env`、配置文件只列出变量名和用途，不写具体值。
6. 不确定的地方**写明"不确定"**，并放进最后的疑问清单，不要猜。

### 二、输出位置和格式

- 输出到 `~/Desktop/锐兴系统交接/`，按下面的编号分成多个 Markdown 文件。
- 每个文件不超过约 40KB，超过就拆成 `05a`、`05b` 这样的分卷。
- 中文书写；表格优先；代码只摘关键几行，不要整段贴。
- 每个文件开头写：生成时间、源码 HEAD commit、所用备份库的文件名和备份时间。

### 三、要写的文件和内容

#### 00-总览.md
- 技术栈和版本（Next.js、前端、SQLite 驱动、主要依赖）。
- 目录结构（列到 2–3 层），每个目录一句话说明用途；各目录代码行数。
- 本地怎么启动、怎么部署、怎么备份（脚本、定时任务、备份存在哪、保留多久）。
- 当前 HEAD、当前分支、未提交改动的文件清单。
- 最近 90 天的 git 提交，按主题归纳成 10–20 条："最近在做什么"。
- 所有分支，以及每个分支在做什么。

#### 01-岗位、账号与权限.md
- 代码里定义了哪些角色（列出原始值），每个角色对应实际岗位。
- 登录方式、密码存储方式、会话/Token 机制、过期时间。
- 每个角色能看到的**菜单清单**（按代码里的实际顺序，含菜单名、页面路径、对应文件）。
- 数据权限：城市/辖区怎么限制、客户池怎么隔离、主管能看到哪些人的数据、老板和行政能看到什么。写出判断权限的代码位置。
- 有哪些导出功能，谁能导出，有没有限制。
- 员工离职或停用时怎么处理，账号和名下客户怎么交接。

#### 02-页面清单.md
系统里**每一个页面**一节，包含：
- 菜单名、URL、所属角色、源文件
- 这个页面是干什么的（一两句话）
- 页面上显示哪些区块、卡片、列表、筛选、排序
- 页面上能做的每一个操作（按钮、表单），每个操作调用哪个接口、写哪张表
- 页面读取的接口和数据表
- 最近 30 天 / 90 天有没有人用（依据：访问日志、或该页面产生的数据写入量；没有依据就写"无法判断"）

#### 03-业务流程与状态.md
按客户的完整生命周期写：
**进线（各渠道怎么进来）→ 分配给客服 → 首次跟进 → 日常跟进 → 定位 → 派单（订单 → 匹配 → 推送 → 试课）→ 成交 → 退费 → 老客户回访**

每一步写清楚：
- 在哪个页面、由谁操作
- 写入哪些表的哪些字段
- **是否记录了操作人和操作时间**（这一点很重要，逐一确认）
- 涉及的所有状态值（列出数据库里实际出现的全部取值和数量），以及状态怎么流转、由哪段代码改变
- 有没有自动规则（超时提醒、自动分配、自动改状态、定时任务）

老师这边也写一遍：**录入 → 定位 → 可接单 → 被推送 → 试课 → 成交 → 回访/维护**

#### 04-数据库.md
- **每一张表、每一个视图**：用途、行数、最早和最近一次写入时间、哪些代码读写它。
- 每张表的字段：字段名、类型、含义、是否可空；重要字段列出实际取值分布。
- 表之间的关系（外键或逻辑关联），画一个简单的文字关系图。
- 有效视图（比如 `effective_*`）的定义，以及哪些作废记录被排除了。
- 成交、退费的幂等和校验是怎么做的（代码位置）。
- 单独列一张表：**空表 / 90 天无写入的表 / 纯技术表（assertion、migration、rollback 等）**。

#### 05-分类规则与算法.md
系统里**所有分类、标签、规则和判定**，每一条都写：名称、在哪个页面出现、精确的计算规则（含阈值）、代码位置、当前各分类的数量。至少要包括：
- **老师经营**：特别关注、定位成功/失败、优质老师、A/B/C/D/E 分档，以及老师列表的排序方式、快捷跟进写到哪里
- **老客户回访**：有哪些分类、每类怎么判定、回访周期、回访结果怎么记录
- **我的线索 / 客服工作台**：客户分类、标签、优先级、超期判定、今日待办怎么生成
- 客户分配规则（新线索分给谁、按什么规则）
- 12 小时跟进率等考核指标的算法
- **派单匹配**：怎么找附近老师、距离半径、评分或排序规则
- **附近老师、附近家长、附近订单**：半径、筛选条件、排序
- **定位**：用哪家地图服务、地址怎么解析成坐标、失败怎么处理、"客户位置补解析"的完整流程、当前客户和老师的定位成功率
- 学生档案是什么、怎么用
- 其他你在代码里发现的任何分类或规则

#### 06-数据分析与指标.md
- 每一个数据分析页面：谁能看、有哪些图表和数字。
- 每一个指标：名称、计算公式或 SQL、数据来源表、时间口径（按发生月、按进线批次、还是按成交月）、是否扣除退费和作废记录。
- 渠道投入（成本）的来源：流量日报 `traffic_reports_v3` 怎么填、怎么汇总，`lib/traffic-monthly-cost.ts` 的分摊逻辑。
- **单独列一张表：同一个指标在不同页面算法不一样的地方**（例如退费金额来源不同）。
- 日报相关：哪些岗位写日报、日报内容、差额核对、更正申请、月度快照的逻辑。

#### 07-新功能-订单.md（重点）
正在开发的订单新功能：
- 它要解决什么问题（从代码、注释、设计文档、提交信息里归纳）
- 涉及的分支、提交、文件、新增或修改的表和字段
- 已经做完的部分和还没做的部分
- 订单的字段和状态流转
- 和现有派单流程（推送、试课、成交）是什么关系，哪些地方重叠

#### 08-外部依赖与集成.md
地图/地理编码、企业微信、短信、文件上传、Excel/CSV 导入（哪些渠道的数据从哪导入、格式是什么）、定时任务、日志。每一项写：用途、配置变量名（不写值）、代码位置、失败时会怎样。

#### 09-数据质量.md
用备份库统计（只给数量，不给个人信息）：
- 渠道/来源字段的所有不同取值和数量（例如闲鱼、咸鱼、直营闲鱼、其他）
- 城市字段的所有不同取值和数量（包括"✖""还未回复"这类异常值）
- 各业务动作中操作人为空的记录数（首次跟进、跟进、订单、派单、回访、成交、退费）
- 客户和老师的定位成功、失败、未定位数量
- 疑似重复的客户和老师数量（同手机号等，只给数量）
- 孤儿记录（关联对象已不存在）
- 投入分不到渠道或城市的金额（按月）

#### 10-使用情况.md
最近 90 天，按岗位（不写人名）统计每个功能的使用次数：新增线索、跟进、定位、派单、推送、试课、成交、退费、回访、录入老师、写日报、看各分析页（如果有访问日志）。用来判断哪些功能没人用。

#### 11-技术债与风险.md
- 超过 1000 行的文件
- 重复实现的逻辑（同一件事写了多份）
- 已经没有入口的死代码、死接口
- 硬编码的城市、人员、阈值
- 测试情况
- 安全问题：密码存储、接口鉴权遗漏、批量导出、SQL 拼接等
- 迁移到云服务器时需要注意的地方

#### 12-疑问清单.md
所有你不确定、需要问老板的问题，逐条列出，并说明你的猜测和依据。

#### 附录-SQL.md
文档里用到的所有统计 SQL，按文件编号归类，方便核对。
